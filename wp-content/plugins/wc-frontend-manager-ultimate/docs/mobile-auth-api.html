Mobile Auth REST API

Phone-number + OTP based authentication for Aaraakart customers and mobile apps. Supports custom SMS gateway and Firebase Phone Auth.

Overview

The Aaraakart Mobile Auth module is delivered as a WCFMu plugin (class-wcfmu-mobile-auth.php) and exposes four REST endpoints under the aaraakart/v1 namespace.

Customers authenticate using their mobile phone number. A one-time password (OTP) is delivered either via a configurable SMS gateway or via Firebase Phone Auth (client-side flow). On success the server returns a signed HS256 JWT compatible with the JWT Authentication for WP REST API plugin.

All endpoints below are relative to this base. Requests must use HTTPS. The Content-Type: application/json header is required for POST requests with a JSON body.

Authentication

After a successful /auth/login or /auth/register call, the server returns a JWT Bearer token. Pass it in the Authorization header for all authenticated requests: 

Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...
ℹ
The token is signed with JWT_AUTH_SECRET_KEY defined in wp-config.php. Tokens expire after 24 hours. Store them securely — do not commit to source control.

JWT Payload

"iss":  "https://aaraakart.com",   // site URL
"iat":  1720700000,              // issued at (Unix timestamp)
"nbf":  1720700000,              // not before
"exp":  1720786400,              // expires at (iat + 86400s)
"data": {
  "user": { "id": 42 }
}

OTP Providers

The module supports two delivery modes, configurable globally or per-vendor:

ModeHow it worksConfig
custom_sms Server generates a random OTP, stores it in a transient, then calls your SMS gateway via a configurable HTTP request (GET or POST). Supports template variables {phone} and {otp} in URL, headers, and body. wcfmu_otp_sms_url
wcfmu_otp_sms_method
wcfmu_otp_sms_headers
wcfmu_otp_sms_body
firebase Client handles Firebase Phone Auth flow (sends OTP via Firebase SDK). Client receives an idToken on success and sends it to /auth/login or /auth/register. Server verifies the idToken via Firebase Identity Toolkit API. wcfmu_otp_firebase_api_key
✓
Per-vendor override: Each vendor can have their own SMS API credentials configured on their profile page at store-manager/vendors-manage/[id]/. Empty vendor fields fall back to the global defaults. See Per-vendor Settings for details.

Send OTP

POST /auth/otp/send Public

Request an OTP for a phone number. In custom_sms mode the OTP is generated server-side and dispatched via your SMS gateway. In firebase mode the Firebase API key is returned so the client can initiate the Firebase SMS flow — no OTP is sent by the server.

Request Parameters
FieldTypeRequiredDescription
phonestringrequired Phone number in E.164 format, e.g. +919876543210
actionstringrequired login or register — stored with the OTP to prevent cross-action reuse
vendor_idintegeroptional Vendor user ID — uses that vendor's SMS API settings. Defaults to 0 (global settings)
Request — Custom SMS
{
  "phone":     "+919876543210",
  "action":    "register",
  "vendor_id": 42           // optional
}
Response 200 — Custom SMS
{
  "success":    true,
  "expires_in": 300,       // seconds until OTP expires
  "mode":       "custom_sms"
}
Response 200 — Firebase
{
  "success":          true,
  "mode":             "firebase",
  "firebase_api_key": "AIzaSy..."  // use to init Firebase SDK
}
⚠
Returns 429 Too Many Requests after 3 OTP requests for the same phone number within a 10-minute window. The client should display a countdown before allowing a retry.

Login

POST /auth/login Public

Authenticate an existing customer. Verify the OTP (or Firebase idToken) and return a JWT if the phone number is linked to a registered account.

Request Parameters
FieldTypeRequiredDescription
phonestringrequired E.164 phone number
otpstringcustom_sms The OTP received by SMS (4–8 digits). Required when provider is custom_sms
firebase_id_tokenstringfirebase Firebase idToken from client-side phone auth. Required when provider is firebase
vendor_idintegeroptional Vendor user ID for per-vendor Firebase API key verification
Request — Custom SMS
{
  "phone": "+919876543210",
  "otp":   "482916"
}
Request — Firebase
{
  "phone":             "+919876543210",
  "firebase_id_token": "eyJhbGciOiJSUzI1NiIs..."
}
Response 200 — Success
{
  "token":      "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
  "user_id":    42,
  "email":      "ravi@example.com",
  "first_name": "Ravi",
  "last_name":  "Kumar",
  "phone":      "+919876543210"
}
Response 401 — Phone not registered
{
  "code":    "needs_registration",
  "message": "No account found for this phone number."
}
ℹ
The OTP is single-use — the transient is deleted immediately on a successful validation. An invalid OTP does not consume the transient, but failed attempts count toward rate limits.

Create a new WooCommerce customer account using a verified phone number. The phone number and email must not already exist in the system. Returns a JWT on success.

Get Profile

GET /auth/me JWT required

Retrieve the authenticated customer's profile. The JWT exp claim is validated server-side — expired tokens are rejected with 401.

Request Header
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...
Response 200 — Success
{
  "user_id":    42,
  "email":      "ravi@example.com",
  "first_name": "Ravi",
  "last_name":  "Kumar",
  "phone":      "+919876543210",
  "roles":      ["customer"]
}
Response 401 — Missing or expired token
{
  "code":    "unauthorized",
  "message": "Invalid or expired token."
}

Error Codes

All error responses use standard HTTP status codes and return JSON with a code and message field.

HTTPcodeEndpointMeaning
400 invalid_phone send, login, register Phone number is not a valid E.164 format
400 invalid_otp login, register OTP is incorrect, already used, or expired
400 invalid_firebase_token login, register Firebase idToken could not be verified
400 phone_already_registered register Phone number is already linked to an account — use login
400 email_already_registered register Email address belongs to an existing account
401 needs_registration login Phone number is valid but has no account — direct user to register
401 unauthorized me Missing, malformed, or expired JWT
429 rate_limit_exceeded send More than 3 OTP requests in 10 minutes for this phone number
500 sms_send_failed send SMS gateway returned an error — check vendor API configuration
500 registration_failed register WordPress user creation failed (WP_Error)

Rate Limiting

To prevent OTP spam, the /auth/otp/send endpoint enforces a per-phone rate limit using a WordPress transient counter.

ParameterDefaultOption key
Max OTP sends3wcfmu_otp_rate_limit
Window600 seconds (10 min)(fixed)
Counter keywcfmu_rate_{md5(phone)}
⚠
When the rate limit is exceeded, the server returns HTTP 429. The client should disable the "Resend OTP" button and show a countdown. The window resets automatically after 10 minutes — no manual reset is needed.

Per-vendor Settings

Each vendor can override the global SMS API configuration from their profile page at store-manager/vendors-manage/{vendor_id}/. Vendor-specific values are stored as user_meta on the vendor's WordPress user.

User Meta KeyFallback (wp_option)Description
wcfmu_otp_providerwcfmu_otp_providercustom_sms or firebase
wcfmu_otp_sms_urlwcfmu_otp_sms_urlSMS gateway endpoint URL
wcfmu_otp_sms_methodwcfmu_otp_sms_methodGET or POST
wcfmu_otp_sms_headerswcfmu_otp_sms_headersJSON string of extra request headers
wcfmu_otp_sms_bodywcfmu_otp_sms_bodyBody template with {phone} and {otp}
wcfmu_otp_firebase_api_keywcfmu_otp_firebase_api_keyFirebase Web API Key
wcfmu_otp_lengthwcfmu_otp_lengthOTP digit count (4–8, default 6)
wcfmu_otp_expirywcfmu_otp_expiryOTP validity in seconds (default 300)

To use a vendor's settings, pass vendor_id in the REST request:

POST /wp-json/aaraakart/v1/auth/otp/send
{
  "phone":     "+919876543210",
  "action":    "register",
  "vendor_id": 42
}
✓
Clearing a vendor field on the profile page calls delete_user_meta(), so the vendor seamlessly inherits from the global default instead of storing an empty override.

Shortcodes

Two shortcodes are available for WordPress page/post editors. They render a two-step mobile auth form (phone input → OTP input → redirect).

Login Form
[wcfmu_mobile_login redirect="/my-account/" vendor_id="42"]
Register Form
[wcfmu_mobile_register redirect="/my-account/" vendor_id="42"]
AttributeDefaultDescription
redirect WooCommerce My Account URL URL to redirect to after successful login/registration
vendor_id 0 (global settings) Vendor user ID — passes through to REST API calls so the vendor's SMS API is used
ℹ
The shortcode forms automatically call /auth/otp/send on "Send OTP", then /auth/login or /auth/register on OTP submission. On success the JWT is stored in localStorage and the browser redirects to the redirect URL.
SMS Body Template Example
// Use {phone} and {otp} placeholders in the sms_body setting
{
  "to":      "{phone}",
  "message": "Your Aaraakart OTP is {otp}. Valid for 5 minutes."
}
